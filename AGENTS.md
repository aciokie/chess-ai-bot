# AGENTS.md - Chess AI Bot Userscript

## Quick Facts
- Single-file Tampermonkey/Violentmonkey userscript: `chess-ai-bot.user.js` (~345KB, ~6000 lines). No build step, no package.json, no lint config.
- Chess.com (primary) + lichess.org (see "Lichess Support" below): `@match` covers play/game/analysis/puzzles/daily pages on chess.com plus all of lichess.org; chess.com board selectors are `chess-board, wc-chess-board`, the lichess board is driven through a virtual shim.
- Engines are downloaded at runtime via ordered multi-source chains (unpkg → jsdelivr → this repo's GitHub release mirror); WASM bytes are SHA-256 pinned before caching. No WASM is committed to the repo. See registry below.
- Browser extension build: `extension/` is a generated MV3 port of the userscript — all features, UI, and the H-panel keybind preserved; all 7 engines ship inside the extension. See "Browser Extension" below.
- Auto-update: `@updateURL` / `@downloadURL` → raw.githubusercontent.com. **Bump `@version` on every push** (currently 11.9.5) or Tampermonkey won't detect the update. `extension/manifest.json` + `src/gm-polyfill.js` carry the same version — `tests/extension.test.js` fails if they drift.
- Only these GM APIs are granted: `GM_getResourceText`, `GM_getValue`, `GM_setValue`, `GM_xmlhttpRequest`, `GM_info`. The `@resource stockfish.js` (unpkg SF19 single JS) is used as the bundled loader JS for `sf19_00`.

## Commands
- Syntax check (the closest thing to a lint): `node --check chess-ai-bot.user.js`
- **ALWAYS PUSH WHEN DONE — standing repo rule**: every completed task must be committed and pushed to `main` (`git push origin main`) without waiting to be asked; unpushed work is not done. Bump `@version` whenever the userscript changed. Never force-push or rewrite pushed history.
- Releases: for engine-file or release-worthy changes, also push a `v*` tag matching `@version` — it publishes the **engine mirror release** (`.github/workflows/release-engine-mirror.yml`): downloads, hash-verifies and republishes existing CDN engine files as release assets (no compilation involved). Pushing `main` alone triggers no CI.
- Tests (offline, zero deps): `node tests/run-all.js` runs registry structure, download-integrity units, the worker-bootstrap simulation, the mirror-workflow cross-check, the extension parity checks, and both Lichess suites (UCI→FEN + read-path/socket-capture). Individual files run directly (`node tests/<file>.js`). Live CDN + pinned-hash verification (~120 MB download): `node tests/verify-engine-sources.js` (options: `--quick`, `--model=<id>`).
- Extension: `node extension/build.mjs` regenerates `extension/src/bot.js` from the userscript (never edit it directly; `--check` verifies sync and exits non-zero when stale). Always rebuild after userscript edits or the parity test fails. `node extension/download-engines.mjs` fetches + hash-verifies the bundled engine files (git-ignored).
- Legacy: `tests/userscript-test.spec.js` is a Playwright smoke test. No package.json — install ad hoc (`npm i -D @playwright/test && npx playwright install chromium`); test 2 assumes a manually logged-in Chess.com session.

## Engine Loading (the part that bites)
- `LOCAL_ENGINES` (~line 89): per-model ordered `sources` chains (`{label, js, wasm, sha256}`) + capability flags + defaults. The caps map drives UCI options, UI rows, and per-model settings — extend this array, don't special-case elsewhere. Every source of a model must serve byte-identical files (same sha256 pin); add new mirrors as extra sources, never change a pinned hash without re-verifying.
- Pipeline (`loadLocalEngine`): IndexedDB cache → source chain download via GM XHR (each source tried in order; any failure falls through to the next) → Worker built from a bootstrap Blob. Downloads are rejected unless Content-Length matches and the WASM SHA-256 matches the pin — corrupted bytes can never reach the cache. A compiled `WebAssembly.Module` is posted back from the worker and cached, so reloads skip the 4-5s WASM compile.
- **Fetch mock (critical)**: the bootstrap worker replaces `self.fetch` to serve only the FIRST fetch call while WASM bytes are unconsumed — the loader makes exactly one fetch, and blob-URL workers make URL matching unreliable. Everything else MUST fall through to the real fetch or Chess.com sockets/CSP break.
- **Loader patch (CSP-safe, since 11.9.0)**: the worker blob is built as `[bootstrapCode, "self.__sfStart = function() {", <engine JS with the ie[e].apply(null,fe) guard pre-applied>, "};"]` — the engine code is a plain function body, so there is **no `eval`/`new Function` at runtime** (lichess.org's CSP forbids eval and blob workers inherit it; chess.com allowed it, so this was found by the lichess live test). The `ie[e].apply(null,fe)` regex patch now runs on the **main thread** (single backslashes — the old template-literal doubling trap is gone). The launch message carries only the WASM bytes (or compiled module); `tests/worker-bootstrap.test.js` runs the joined blob parts and guards the patch + launch flow.
- Heartbeat: worker posts a beacon every 3s; the main thread probes `isready` every 15s; only 6 consecutive misses with no recent beacon (~90s) declare the worker dead. Worker errors auto-restart the engine after 2s.
- Watchdog: 5-minute hard load timeout, then a 120s retry cooldown (mainly trips when IndexedDB is blocked, e.g. incognito).
- Auto-heal: a WASM Compile/Link error purges the model's cache once (`purgeModelCache`) and re-downloads; if the reload fails again, the 2s auto-restart is skipped so it can't hot-loop (`engineHealMap` tracks this per model per page).
- Settings: global `bot_<key>`, per-model `m_<modelId>_<key>` (hydrated into the `settings.local*` working copies by `loadModelSettings()`). `engineMode` is forced to `"local"` at startup.
- Turn gating: analysis and auto-move only run when `isOurTurnNow()`; FEN comes from `state.board.game.getFEN()` via `getRawBoardFEN()`. Board reads are memoized with a 2-5s backup poll.
- Anti-cheat: after every 12-25 analysis ticks `shouldPauseAnalysis()` skips 0.7-2.5s (disabled in bulletMode).

## Lichess Support (v11.9.5)
- Two platforms: `IS_LICHESS` (hostname lichess.org) switches the board to a *virtual shim* (`Lichess.board()`) so the whole analyze/auto-move core runs unchanged. Chess.com-DOM visuals are replaced by `LichessOverlay` — an SVG layer inside `.cg-wrap` (viewBox `0 0 8 8`, orientation-aware) that draws move highlights, PV arrows and the red threat arrow, plus a slim native-style eval bar (`renderEval`, white/black split + score; `EvalBar.create/update` route to it via `IS_LICHESS`). Move arrows use lichess green (#81b64c) when the user kept the stock cyan `highlightColor` (#00eeff). Panel default position on lichess is top-left (fresh profiles).
- **Read (state → FEN)** — the board DOM is the ground truth; `/game/export` is NOT:
  - game ids are 8-char (legacy `GameId`) AND 12-char (current `GameFullId` = `GameId` + 4-char playerId) — the URL regex must accept `{8,12}` (`kH1p9xPN` vs `r97K4Zr3I6i0`; requiring exactly 8 silently broke every new live game). A *player's* live game page is always routed through the 12-char FullId (`GET /game/$fullId<\w{12}>` → `Round.player`), while the **export route is `GET /game/export/$gameId<\w{8}>` — exactly 8** (verified against lila `conf/routes` + `modules/core/src/main/id.scala`). So `/game/export/{12-char}` 404s on EVERY current live game; always query with `id.slice(0, 8)` (`GameFullId.gameId === GameId.take(8)`; identity for legacy ids). v11.9.1 shipped the 12-char URL straight into the export URL → live games never got a FEN and the bot sat idle. Vs-computer games hide this: `Setup.redirectPov` sends them to the 8-char `Round.watcher` route (`/game/{id}`), so AI games export fine — that's why they worked while every real rated game 404'd.
  - placement: parse `cg-board piece` elements (absolute px `translate`), orientation from `.cg-wrap.orientation-white|black`; the reader returns null mid-animation (fractional transforms) so animated reads can't corrupt the model.
  - side to move: chessground's `square.last-move` destination still holds the mover's piece → the opposite side is to move (fallback: SAN-count parity from export).
  - castling: home-square heuristic on each resnap; ep "-"; counters `0 1` on resnap, then advanced exactly by socket move frames (`{"t":"move","d":{uci,san,fen,ply}}`) via `lichessUciToFEN` (unit-tested in `tests/lichess-uci-fen.test.js`). Every move frame also kicks `checkAndAnalyze()` instantly; a DOM-vs-model placement mismatch self-heals on the next poll.
  - `/game/export/{id8}?moves=true` (always the 8-char id — see above) is **laggy for AI/correspondence games (observed frozen for minutes)** and needs `Accept: application/x-ndjson` (else PGN). It is used ONLY for game presence, players→color (`user.id` vs username), status and SAN-count parity. On any export failure the poll now calls **`_bootstrapFromDOM()`**: manipulable board → `status="started"`, color from orientation, FEN from the DOM readers (turn = White at cold start, else keep the model), then kicks `checkAndAnalyze()` — a dead export can never wedge the adapter again (socket frames + DOM resnaps carry the game). `/api/account` rejects session cookies (401, token-only) — the username comes from the top-bar account menu (`header ...user-link`); a generic "first /@/ link" can pick a RECENT-GAMES opponent on the homepage (observed).
  - Spectator safety: `board()` returns null unless `.cg-wrap.manipulable` exists (players' boards only). Root-URL safety: bare `/analysis` and `/training` are 8-char words that match the id pattern AND have manipulable boards — `gameIdFromUrl()` rejects lila's top-level route words on the bare-root form (`_nonGameRootWords`, from `conf/routes`); real games always redirect to `/game/{id}`.
- **Write (moves)**: player round sockets live at `/play/{gameId}{playerId}/v6` (= `/play/{the 12-char FullId}`; spectators use `/watch/{id}/…/v6`, so the `/play/` filter excludes them). There is **no `/socket` suffix** — the old matcher never actually matched and only survived through its readyState fallback. Capture pipeline (all three layers needed):
  1. **Constructor Proxy** over `PAGE.WebSocket` — sockets created after boot land in the shared registry `window.__sfLichSocks` immediately; the trap returns the real socket, so the site sees zero behaviour change.
  2. **`WebSocket.prototype.send` probe** (flag `__sfPatchedSf11`) — catches the round socket that already existed before the bot booted: lichess sends a keepalive `'p'` ping every ~2.5s, so the registry learns it within seconds. A sibling instance with the older `__sfPatched` flag must NOT block the wrapper.
  3. **`_syncSockets()` adoption** — pulls `/play/` sockets from the registry into `_socks` (hooks their message events). Called from `init`, **every poll tick, and every `sendMove`** — THIS was the v11.9.2 fatal gap: the probes only ever ADD to the registry, and `_socks` was synced once at init (i.e. before the round socket's first ping — or before a reconnect), so sendMove logged "no round socket captured yet" forever while the socket sat in the registry. Never only sync adoption at init again.
  All of the above **re-verifies on every sync** (`_ensureCapture`, v11.9.5): if `PAGE.WebSocket` is no longer our proxy reference (`PAGE.__sfProxySf11`), it is re-wrapped; if the live prototype lost the send marker, the probe is re-installed. This self-heal exists because a third-party extension or a stale instance can replace `window.WebSocket` *after* our patch and blind capture for an entire game — after 3 consecutive send misses `sendMove` emits a one-line `capture diagnostics — ctorProxy=…, sendProbe=…, registry(…): …urls…` so the broken link is visible without DevTools spelunking.
  Failed sends retry up to 6× at 1.2s (`state._lichessSendRetries`, reset on success/new FEN) so the opening move can't stall on a capture that lags a ping cycle. Moves go out as the exact site frame `{"t":"move","d":{"u":"e2e4","a":<ackId>}}` (ack base 90000+, 8s de-dupe per UCI). Programmatic DOM pointer events do NOT work (chessground ignores untrusted input) — socket replay is the mechanism.
- Auto-move gates: the `scheduleAutoMove` legality check and the OpeningBook legality check are bypassed on lichess (`lichessSendMove` marker); the server validates. The shim's `getLegalMoves()` is empty by design.
- CSP notes (found the hard way): lichess's home-page CSP blocks WASM entirely, but **game pages allow it** (meta tag includes `unsafe-eval`). `loadLocalEngine()` therefore **defers on any lichess page whose meta CSP lacks `unsafe-eval`** (home, lobby, waiting/challenge screens): attempting a load there left a "worker alive … (compiling)" heartbeat looping for as long as the tab stayed open (observed at 1500s!) while self-heal re-downloaded engines on a page that can never compile them — the biggest "lichess feels so slow" contributor. The install-count ping (`countapi.mileshilliard.com`) is skipped on lichess — `connect-src` blocks it, so it only ever produced console errors there. Page-context fetches to CDNs are `connect-src`-blocked → the userscript relies on privileged `GM_xmlhttpRequest` and the extension on bundled `chrome-extension://` files (allowed on game pages, verified). The worker bootstrap is deliberately **eval-free** (engine code shipped as the `__sfStart` function body) and polyfills `instantiateStreaming` through bytes. `WebAssembly.Module` is cloneable, NOT transferable — never put it in a `postMessage` transfer list.
- Performance (v11.9.3): per-engine-info UI work (PV arrows / lichess SVG overlay rebuild / panel DOM) is throttled to ~8Hz (`state._lastInfoUiAt`; the final `processBestMove` refresh stays unthrottled) — the engine streams dozens of info lines per second and each one used to rebuild the whole overlay. Combined with the CSP gate above this addresses the "script is sooo slow on lichess" reports.
- Background tabs (v11.9.4): hidden tabs throttle MAIN-THREAD timers (min 1s; "intensive throttling" after ~5 hidden minutes → as little as ONE wake-up per minute) — observed live as `Playing best move: f8e7 after 532ms` + ~10 idle poll cycles before `playMove` ran. Every timing-critical path runs on **`BgTimers`** (Blob Worker echo-timer; worker timers escape throttling; falls back to plain setTimeout): lichess poll (`_schedule`), `scheduleAutoMove`, glance + book delays, send retry, backup + rematch polls. `document.hidden` zeroes the humanizer delays; `visibilitychange` kicks `checkAndAnalyze()` + `Lichess._poll()` on tab return. Wedge-proofing riding along: every applied move frame clears `state.lastSanitizedBoardFEN` (the dedupe can't stay shut on a real move), and a two-tier **analysis watchdog** (recency via `state.lastEngineOutputAt`: 20s silent → reset + re-dispatch; 60s → terminate + rebuild worker) replaces "dead until Analyze is pressed". **Verified live**: tab hidden for the whole session, 80–140ms per `analyzeLocal → bestmove → playMove → sent` cycle, game won 1-0 on time. To timestamp page logs: `console.log = (...a) => orig('[' + new Date().toISOString().slice(11,23) + ']', ...a)`.
- Live verification harness (Playwright MCP **extension bridge**, real account — use for any lichess read/write change): create a challenge link (creator = White) via the lobby, then join it as an anonymous opponent from a fresh Brave profile (`chromium.launchPersistentContext` with Brave's exe) and let the bot auto-play. Gotchas that cost time: the bridge cannot create isolated contexts (`Target.createBrowserContext: Not allowed`); fresh profiles hit Cloudflare ("Just a moment…") unless launched with `--disable-blink-features=AutomationControlled` + `ignoreDefaultArgs: ['--enable-automation']` and warmed up on the homepage first; the anon join button is exactly **"JOIN THE GAME"**; guest turn detection must read chessground's last-move destination piece (clock classes carry no turn marker); lichess pauses the clock while the opponent is disconnected (a closed guest never flags); the waiting/challenge `/game/{id}` screen also blocks WASM (engine correctly defers there). To run the bot inside the real browser tab: bridge `browser_run_code_unsafe` + `page.addInitScript`, GM_* shim tunneling through `exposeFunction`; neutralize the duplicate guard in the injected copy while setting `data-sf-bot-active` at document-start so any stale extension instance skips itself. `opencode.jsonc` (git-ignored, project-local) configures that bridge.

## Browser Extension (extension/)
- **MAIN-world requirement**: `bot.js` runs with `"world": "MAIN"` because chess.com's `wc-chess-board.game` is a page-world custom-element property — isolated content-script worlds see the element as a plain `HTMLElement` with `game === undefined`, which silently disables ALL analysis/auto-move in live games (verified by instrumented bisect). Because `chrome.*` is unavailable in MAIN, `src/ext-urls.js` (isolated, document_start) publishes the extension base URL as the `data-sf-ext-base` DOM attribute — DOM attributes are shared across worlds and `extURL()` reads it. Never move bot.js back to the isolated world, and never rely on cross-world JS properties (only DOM state and postMessage cross worlds).
- **Duplicate-instance guard**: the bot first checks `document.documentElement[data-sf-bot-active]` (DOM attributes cross JS worlds); a second injection skips itself with a clear message. This covers the classic confusion that an extension reload does NOT re-inject into already-open tabs (stale instance keeps running) and userscript+extension coexistence. **After reloading the unpacked extension, refresh open chess.com tabs (F5).**
- `extension/src/bot.js` is GENERATED from the userscript by `extension/build.mjs` — the transforms are additive only (header, `extURL()` helper, bundled sources, bundled fast paths). Byte-identical regeneration, identical element ids/settings, the H keybind, and feature markers are enforced by `tests/extension.test.js`. Edit the userscript, then rebuild.
- All 7 engines are bundled in `extension/engines/<model>/` (git-ignored; fetch via `extension/download-engines.mjs`, SHA-256 pinned to the same hashes as the userscript/mirror). Engine load order: direct extension-file worker (browsers block extension-URL workers from content scripts, so this attempt is once-per-page and `console.debug`-only) → the normal fetch/compile pipeline reading the extension files locally via the GM shim (no network) → the CDN chain as last resort. Normal loads must produce ZERO `console.warn`/`console.error` from `[SF Engine]` (the browser E2E asserts this).
- `src/gm-polyfill.js` shims the GM_* APIs on localStorage (`cabe_ext_*` keys) + fetch. Panel behavior is preserved exactly: starts hidden, **H toggles**, ✕ hides, Alt+B toggles bullet mode.
- Real-browser E2E: `node extension/e2e-test.mjs` (needs a Playwright install via `--playwright=<path>`/env; auto-discovers Chromium/Brave/Edge) — verifies panel injection on live Chess.com, the H keybind, bundled local engine load (no CDN), a model switch, the cached reload, a REAL vs-computer game (auto-move must reach >= 3 positions with engine bestmoves logged), navigation recovery (returning mid-game shows Continue/New Game; pressing Continue must resume play), and auto-rematch (enabled via the panel checkbox: after a resign the bot itself clicks Rematch/New Game and a fresh game starts moving). Artifacts in `extension/e2e-artifacts/` (git-ignored). Gotchas it encodes: strip Playwright's default `--disable-extensions`; chess.com's own modal overlays intercept pointer events, so button checks use DOM clicks; guest games on /play/computer start via the setup panel's "Play" button; a PAUSED vs-computer board reports `getPlayingAs() === undefined` and the bot correctly idles until Continue resumes it.
- Manifest notes: CSP needs `'wasm-unsafe-eval'`; **never add `blob:` to `worker-src`** — it makes Chrome silently refuse to load the entire extension (verified by manifest bisect; content-script blob workers work without it). Engine files must remain listed in `web_accessible_resources`.
- `extension/icons/` — app icon: hand-crafted `icon.svg` (editable source) + rendered 16/32/48/128 PNGs, wired to manifest `icons` + `action.default_icon`; the userscript's `@icon` points at the 128px PNG on raw.githubusercontent. Regenerate by rasterizing the SVG through any headless browser (Chromium screenshot at 512, then bicubic downsample). `tests/extension.test.js` verifies the declared icons exist as real PNGs.

## IndexedDB Schema
- DB `sfEngineCache` (v2), store `engines`; `{cacheKey}` = model id. Keys:
  - `{cacheKey}_js` / `{cacheKey}_wasm` — raw downloaded text/bytes
  - `{cacheKey}_patched` — {jsCode, wasmBytes} patched-worker payload (fastest bytes path)
  - `{cacheKey}_patched_module` — {v: MODULE_CACHE_VERSION, module} compiled module
- Bump `MODULE_CACHE_VERSION` (currently 1) when changing the worker bootstrap so stale compiled modules are discarded.

## Debugging
- All logs are prefixed `[SF Engine]`. Markers: `loadLocalEngine START`, `Download attempt N/M via <label>`, `Source <label> failed`, `All download sources failed`, `Received uciok`, `Engine ready in Xs`, `Auto-heal: cache looks corrupted`, `engine alive at Xs, still initializing`, `worker alive at Ns (compiling)` (WASM loop — CSP-blocked page), `heartbeat miss N/6`, `analysis stall healed` / `analysis watchdog: ...` (self-heals fired), `Auto-rematch: clicked "..."` / `Auto-rematch: accepted incoming rematch offer`, `Lichess: round socket captured (...)`, `round socket not captured yet` (capture pending — sends retry), `capture diagnostics — ctorProxy=…, sendProbe=…, registry(…): …` (capture chain broken; see the Write bullet), `engine load deferred` (CSP gate).
- `state`/`settings` are IIFE-scoped — but on lichess `window.__sfLichess` (live adapter) and `window.__sfOverlay` are exposed for console debugging: `__sfLichess.state()`, `._fen`, `._gameId`, `._socks`, `._sentUci`.
- Toggle "Debug logs" in the script UI to enable the gated `log()` output. `node --check` only catches syntax errors; runtime issues surface in the page console.

## Common Issues & Fixes
| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Engine stuck "Loading..." for 5 min | IndexedDB blocked (incognito) | Use a normal window, or press Reinstall |
| "Engine worker unresponsive" | Worker dead/blocked >90s (broken fetch mock, CSP) | Clear cache and reload; check network |
| "All download sources failed" | Every CDN unreachable (VPN/blocker) | Check network; try an asm.js model (no WASM needed) |
| CompileError / LinkError on load | Corrupted cache or mismatched JS/WASM pair | Auto-heal purges + retries once; if it repeats, press Reinstall or run `node tests/verify-engine-sources.js` |
| Auto-move not working | Not your turn, or `autoMove` disabled | Check `isOurTurnNow()` logic and settings |
| Lichess: live game shows "poll failed (HTTP 404)" and never analyzes | Live games sit at the 12-char `GameFullId` URL, but lichess's export route only matches `\w{8}` — pre-11.9.2 sent the 12-char id straight to `/game/export/` | v11.9.2 exports via `id.slice(0, 8)` + `_bootstrapFromDOM()` keeps the adapter alive even if export dies |
| Lichess: "no round socket captured yet" forever, bot analyzes but never moves | (a) 11.9.2: probes only ADD to `__sfLichSocks` and `_socks` was adopted once at init; (b) 11.9.5: a stale third-party wrapper replaced `window.WebSocket` after our patch | v11.9.3+ adopts on every poll + send; v11.9.5 re-verifies and re-wraps the instruments every sync (`_ensureCapture`) and logs `capture diagnostics` after 3 misses. Stale-tab check: the console line number in a stack pins the running build (`src/bot.js:1039` = v11.9.3, `:1090` = v11.9.4) — an extension reload never re-injects into open tabs, F5 them |
| Lichess: tab feels laggy / "worker alive at 1500s (compiling)" looping | Engine was being loaded on pages whose CSP blocks WASM (home/lobby/waiting screens) and the per-info UI rebuilt the overlay dozens of times per second | v11.9.3 CSP gate defers engine load + ~8Hz throttle on per-info UI work |
| Bot stalls on long games, must click Analyze; never moves while alt-tabbed | Hidden tabs throttle main-thread timers (up to 1 wake/min) + a wedged search had no recovery path | v11.9.4: `BgTimers` worker timers on all critical paths, humanizer skipped when `document.hidden`, `visibilitychange` catch-up, move-frame gate reset, analysis watchdog |
| Auto-rematch never starts a game | Pre-11.8.0 logic only *accepted* offers and its modal selectors are gone from the current site | v11.8.0 `attemptRematch()` clicks Rematch → Play Again → New Game (`clickInitiateRematch`); game over = `.game-over-modal-shell-container` |
| Incoming rematch gets auto-declined | Anti-draw `declineDrawOffer()` blindly clicked any "Decline" button (including rematch dialogs) | v11.8.0 never declines rematch dialogs — it accepts them when Auto-Rematch is on, else leaves them |
| Automation does nothing until "Analyze" is clicked manually | The analyze-trigger dedupe (`clean !== lastSanitizedBoardFEN`) got seeded without a real analysis: new-game reset didn't clear it when the new position equals the old one (startpos after instant/aborted rematch), and `undefined===undefined` turn values counted as "our turn" while the board initialized | v11.8.1 clears the FEN dedupe + completion marker in `resetTransientStateForNewGame()`, strict side resolution in `checkAndAnalyze`/`isOurTurnNow` (undefined ≠ our turn), and a throttled stall self-heal that force-analyzes when the gate is provably wedged |
